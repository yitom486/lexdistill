# Lingua Studio 教材导入架构

更新：2026-10-01，按用户批准的目录与运行监视计划分步实施。产品入口是 Tauri 桌面；`apps/web` 是桌面 WebView 的 React 代码目录。

## 运行监视（P2）

### 模型内容与系统身份

原生提交工具只接收 `content`，不要求模型生成正文、生词、知识点、例句、习题或选项 ID，也不接收模型提供的 documentId/lessonId/assignmentId。Gateway 由原生 `onTurnStarted` 回调绑定当前运行轮次，拒绝不同轮次或未启动轮次的提交，再生成内容 ID。知识点、选项与匹配答案使用本次数组从 0 起的下标，验证边界后转换为持久化 ID；数据库正典结构保持一致。

`tocId` 和 `sourceRefs.blockId` 是已提供材料的定位引用，模型原样引用；当前目录节点、目录路径、完整子目录和实际物理页均随章节发送。题型、来源、正文/讲解分离和答案结构仍需校验，供后续 UI 正确渲染；无法据此证明正文语义完整。

模型工具中所有内容及例句的 `tocId` 必填。`sourceRefs` 只提交当前材料的 `blockId` 和可选的表格 `row`；系统从对应解析块映射真实物理页，存储正典仍保存 `page`。未知块及越界行拒绝，不猜页、不兼容旧工具参数。

工具说明的合法枚举与字段来源名称从实际 schema 生成。结构校验一次返回全部结构问题；结构合法后汇总目录、来源和交叉字段问题。反馈使用 `content.knowledgePoints.0.examples.0.tocId` 等模型实际字段路径，不包含系统生成的内容 ID。只有全部校验通过才建立可保存候选。

每个 Worker 使用独立原生线程；同一 Worker 顺序复用线程，前章和修正历史可进入后章上下文。此设计不是每章新建空白上下文，监视应展示当前输入并允许查看同线程先前交互。

### 模型交互故障修复（S0，2026-10-01）

共享 Codex 连接的通知按真实 threadId/turnId 隔离；旧轮和其他线程的事件不能结束当前等待。原生工具调用身份使用当前 Codex 0.159.2 生成协议中的 callId，已废弃的 itemId 不保留兼容。明确的业务校验反馈返回模型，运行时和数据库内部异常不透出；新轮纠正同样携带具体校验问题。

原页渲染遵循 pinned pdf-inspector 每次最多 8 页的限制，分批保留全部章节页图。模型附件采用应用总字节预算 32 MiB，不再把目录渲染的单次页数当成正文附件上限。MinerU failed 回执的 err_msg 和远端任务身份留作诊断，不臆造服务未提供的深层原因。

目录定位、目录模型与独立保存、正文任务共享 `traceId`；创建前没有教材/job 身份，后续事件保存实际身份。桌面“目录运行详情”“运行详情”及章节点击入口只显示本次记录。实际提示词、原生工具注册信息、公开模型事件、提交候选、校验、重试与数据库事务回执由 Gateway 捕获，不补造此前未记录的历史。

诊断写入固定 `textbook_import_events`（v035）。列表只查元数据，正文/参数详情点击后查询；流式文本按活动批次合并，SSE 用全局递增 sequence 补取并去重。界面按章节选择，默认“模型过程”，另有“解析结果”“保存结果”；解析只显示最终材料或失败原因，不列上传/轮询等解析事件。最近一轮默认展开，历史轮次和同线程此前章节默认折叠；刷新保留人工选择与展开状态，关闭重开从持久化记录读取。

模型过程显示实际章节提示词、随输入发送的目录路径/子目录/物理页、原页附件，以及 Agent/线程和原生轮次绑定。每个 callId 的实际参数、字段校验、纠正反馈和事务回执集中展示；系统生成 ID 后的候选需展开读取，保存成功以事务为准。会话工具定义来自 Adapter 实际注入声明；引擎没有提供时明确标注，只显示实际 Gateway 使用说明，不另造 schema。应用未捕获的引擎内置提示词、隐藏上下文或历史压缩不臆造为完整模型上下文。

校验候选与历史事务回执保留在交互记录；“查询数据库当前保存内容”读取当前 AST 版本并附读取时间，两者分别展示。事件存储失败显示记录不完整，不能把已经提交的教材改判失败。目录模型返回时赋予草稿 ID，并按工具提供的父下标转换 parentId；桌面不再猜父节点或重建保存身份。

验收覆盖真实工具/Repository/SQLite 两 Worker 记录、SSE 游标补取、数据库重开、用户隔离、诊断失败，以及隔离 DOM 运行时里的真实 Base UI 弹窗关闭重开、历史折叠与按需读取。模型是受控测试边界，未试跑真实模型或处理现有教材。

## 导入路径

1. 原生文件选择器取得本地 PDF 路径。Gateway 读取文件，按 SHA-256 查询当前用户已保存的教材；改名不改变身份，同名不同文件不匹配。
2. 检测展示实际逐课正文、生词、知识点、习题及预习/总结统计。已有教材全部就绪可直接打开；部分完成可复用已确认目录，只处理未完成课次。完成判断不使用数量阈值或名称推测。
3. 新教材通过书签/局部探测选择目录范围，经专用模型工具提交目录草稿。用户确认时按“印刷页码 + 本次目录结束页”换算 PDF 物理页，调用独立保存接口立即建立目录底稿与章节槽位，并保存文件指纹，不需要启动正文提取。结果可整体或逐项修改并独立保存。再次选择同一份文件自动载入已存目录；明确点击重新识别才启动探测和模型。
4. 解析生产者与固定 Agent 会话池初始化同时启动。数字原生 PDF 直接读取文字；扫描正文按章节物理页裁切并进入 MinerU。逐页材料和必要原页图片就绪即交给有界队列；会话空闲即可消费，通过原生工具独立校验保存。
5. 每章提交成功立即发布已保存统计；全部课次实际 `ready` 才完成。失败章可重试，已保存章默认跳过。界面按目录顺序展示。

```mermaid
flowchart LR
  A[确认目录、换算物理页] --> B[独立保存目录底稿与槽位]
  B --> E[用户启动正文提取]
  E --> C[并发原生文本 / MinerU 章节解析]
  E --> D[预建固定会话并注入工具]
  C --> Q[有界章节队列]
  Q --> D
  D --> T[原生提交工具]
  T --> V[独立校验与任务绑定]
  V --> S[章节事务：AST + 派生行]
  S --> R[成功回执与阶段进度]
  R --> D
```

## 职责和会话生命周期

### 2026-10-01：目录任务与模型输入（P1）

任务清单由统一的 `planTextbookTasks` 按实际目录 ID/父节点生成。一课包含其子目录；课次以外的独立小节也组成任务。单元/章容器汇总子任务，父项缺失、循环或无内容子项显式拒绝。目录复用保留四级层级、ID 和父节点，不按上一课或相似标题重建关系。

模型实际输入携带目录路径和本任务的完整条目（ID、标题、层级、父节点、顺序、物理起止页）及对应文本。任务可以乱序完成，读取按目录顺序。原生提交只允许任务锚定节点；容器不要求生成虚构正文。

进度、导入检测和 `allLessonsReady` 覆盖独立部分；现有计数字段 `lessonCount/totalLessons` 在流水线与检测中统计提取部分，桌面明确显示“部分”，另显示实际目录项和课次数。目录保存回执及 AST 的 `totalLessons` 仍表示课次数。

P1 集成验证实际会话收到的目录结构和页码、独立部分失败时不能全书完成、恢复只处理未完成部分，以及桌面重用目录保持原始身份和层级。模型输出为受控替身，不代表真实模型语义质量已验收。

| 位置 | 职责 |
| --- | --- |
| `application/textbook-outline.ts` | 文件指纹匹配、独立确认保存目录；不启动正文解析/Agent |
| `application/textbook-pipeline.ts` | 固定目录、启动两侧、队列背压、阶段重试、取消和结算 |
| `application/pdf-import/lesson-content-slicer.ts` | 按物理页裁切与提取；扫描正文进入 MinerU，成功页段复用，单章失败隔离 |
| `application/lesson-batch-extractor.ts` | 固定数量会话、工具注入、模型发送与事件消费；没有 Repository 依赖 |
| `tools/library-lesson-commit-tool.ts` | 已登记会话的执行入口；只允许当前用户/章节/尝试提交 |
| `application/lesson-submission.ts` | 参数格式、目录覆盖、来源、题型校验；登记有效候选与保存回执 |
| `storage-sqlite/adapters/library/commit-lesson-knowledge.ts` | 提交身份和规范 AST 同事务保存，所有行表由底稿派生 |

正文入口使用现有 `AgentAdapter` / `AgentSession`。本轮替换了缺少自定义原生工具回执接口的 `agentpools` 教材入口；不增加厂商业务依赖。

池内正常会话持续复用；当前 Turn 结束、绑定解除后才接下一章。同章格式重试保留同一线程，执行端按原生轮次身份拒绝旧提交。仅运行时故障触发会话替换，并记录故障原因；同章下一次生成之前先关闭故障会话，避免迟到响应干扰新轮次。替换失败结算该章，其他 worker 继续。初始化失败不静默缩小池。

工具成功回执以事务提交为准。已保存后发生 Turn 故障仍算成功。普通文本、JSON 文本和 Turn 完成均不能代替工具回执。提示词包含语言、当前目录节点、完整目录、正文、补充习题设置和工具名称，不发送任务身份、示例或 JSON 模板；原生协议所需参数 Schema 只走工具注册。

## 规范章节内容

P4 阅读使用同一任务规划，保留独立 `section` 入口，课次数量只统计实际 `lesson`。各任务保留真实祖先路径及子树；正文、生词、知识点、习题按 `tocId` 和实际父子关系呈现标题与物理页。来源在目录内容组显示，知识点原书讲解、AI 讲解和例句独立展示。不按文字内容猜归属，也不自动拆分或重写已存混写段落。

运行详情“模型候选”以实际工具参数渲染，不等同保存成功；“数据库当前保存版本”按需读取 AST，并查询派生行数量，显示读取时间与节点身份。两处共用目录内容展示组件，原始记录字段仍可展开。历史目录标题来自本 trace 的启动快照，不用当前教材覆盖当时的目录。

提交校验先确认调用所属原生轮次，再校验无 ID 内容格式和数组引用；系统生成 ID 并绑定当前教材/章节/尝试，模型不能更改归属。全部内容及 AI 例句需有本任务内 `tocId`。拒绝反馈含字段路径和合法枚举；新 Turn 与仅保存重试使用不同阶段。

模型首响应与无活动期限集中在 `TextbookPipelineSettingsSchema`，默认分别 60000 / 120000 毫秒，桌面可配置并记住。公开响应活动重置后续期限，超时撤销本次工具提交资格并中断 Turn；迟到提交不能写入。正常章节与格式重试仍复用线程，运行时故障才替换会话。已校验候选保留给保存重试。

持久化内容契约：`packages/document-model/src/lesson-content.ts`；模型提交契约：`lesson-proposal.ts`。模型数组下标经系统转换为下述持久化关联 ID。

- `coverage`：当前章及全部子目录 ID 逐项报告 `EXTRACTED` / `UNREADABLE`。缺项、未知 ID、无法辨认或没有关联内容的小节不能标记成功。
- `blocks`：`PARAGRAPH` / `DIALOGUE`，文字、角色、译文和来源明确。正文是模型纠错后的结构，不保存 OCR 文本作为正式正文，不用 Markdown 正则猜角色。
- `vocabularies`：词面、读音、词性、释义、声调、独立 `aiExplanation` 和例句；AI 讲解不混进 `gloss` 或正文。v036 将讲解同事务派生到 `textbook_vocab.ai_explanation`。
- `knowledgePoints`：原书 `textbookExplanation` 与补充 `aiExplanation` 分开，例句各自记录来源。
- `exercises`：单选、多选、填空、翻译、排序、匹配、简答；答案分别使用 `text`、`optionIds`、`pairs`，检查选项引用、排序覆盖和匹配结构。
- `source` 为 `TEXTBOOK` / `AI`；译文、注音、释义、答案、解析、接续的字段来源另记。原书题干可以搭配 AI 答案和解析。
- 新增 AI 习题无需原书目录有练习项，但不能替代原书已有目录项的覆盖要求。用户可以关闭新增习题。
- 预习和总结属于 AI 导学。桌面渲染显示来源；阅读保持 TTS、收句子和导师入口。

目录与格式校验只提供结构证据，不能证明正文语义完全正确或原书没有遗漏。会话复用保留历史上下文，提交绑定约束写入归属，不宣称清空模型上下文或消除历史 token 成本。

## 存储

六层映射：`documents` → `textbook_lessons` → `textbook_lines` → `textbook_vocab/textbook_grammar` → `textbook_exercises`。底稿 `documents.ast_json` 是 SSOT。

目录条目存于现有 `textbook_lessons`（标题、层级、父节点、顺序、物理起止页），这张表同时承担章节槽位和状态，不额外创建 `textbook_toc`。`POST /api/documents/:userId/textbook-outline` 经既有事务保存底稿和派生目录行；新目录状态为 `pending`，检查结果明确提示“目录已保存，正文尚未提取”。后续提取沿用返回的教材 ID。再次确认同书同标题和物理页的条目复用原身份，保留已就绪正文；没有授权覆盖时，遗漏已就绪条目会拒绝写入。

每章在一个短事务内：检查既有课次槽位、检查 `submission_id`、更新规范 AST、全删全插派生行与 FTS、提交。乱序完成不会改变目录 `sort_order`。同次提交重复调用返回已存内容，不重复覆盖。任一派生写入失败，AST、正文及 ready 状态整体回滚。

v034 同步最新 DDL、Drizzle schema 和前向迁移：

| 表 | 新增字段 |
| --- | --- |
| `textbook_lessons` | `content_json`、`submission_id` |
| `textbook_lines` | `block_id`、`kind`、`source`、`toc_id`、`field_sources_json` |
| `textbook_vocab` | `source`、`toc_id`、`field_sources_json` |
| `textbook_grammar` | `source`、`toc_id`、`ai_explanation`、`field_sources_json` |
| `textbook_exercises` | `source`、`toc_id`、`answer_json`、`content_json`、`field_sources_json` |

`passage_md` 是整理后正文的文本投影，不是正文解析入口。词汇、知识点和正文派生时不再截断内容。结构化 JSON 导入也经同一 AST 校验和投影；客户端保存规范 AST，展示模型不写成底稿。

旧教材示例、补种、旧状态推测和文本 JSON 回填已删除，不做教材数据兼容。已发布迁移保留，新维度通过前向版本升级。本次 Plan 33 未清空、覆盖或重新提取用户已有教材；先前开发阶段的清库记录不代表当前数据状态。

## 解析、资源和重试

原生 PDF 运行时继续提供文字提取、原页渲染和目录探测所需 OCR。扫描正文由并发 MinerU 任务处理；解析并发与 Agent 会话数各自独立设置。

每个章节按可配置页数上限裁切；默认遵循云端 200 页/200MB 限制，文件超限明确拒绝。成功页段保留；本次执行内轮询/下载失败继续已有任务。应用限制同时解析的章节与待模型消费队列，不用全书解析结果阻塞首章保存。

桌面记住云端/本地选择、本地地址/档位、识别语言、解析章节并发、每任务页数、解析超时，以及模型、思考等级、会话数、队列容量、各阶段重试和补题偏好。默认与范围集中在 `textbook-pipeline-settings.ts`；不硬编码模型或教材内容。解析并发不等于本地模型内部线程数。

解析故障只重试当前章；格式、覆盖、来源引用问题反馈模型，由调度器控制新 Turn 次数；越界不改 ID 放行。临时存储故障保留已校验候选，只重试保存，不重复生成。

取消拒绝迟到工具提交，停止新批次及 HTTP 等待；已被解析服务接受的任务可能继续。网关退出取消后台任务并释放会话。已提交章是恢复检查点；在途解析材料、远端任务检查点和队列不跨进程持久化。

## 验收证据

集成测试覆盖真实 SQLite/Hono/HTTP、固定线程复用、首章先保存、背压、目录/来源/题型拒绝与修正、幂等、事务回滚、写库重试、会话故障、取消及配置传递。原生扫描 PDF/ONNX/OCR 测试保留用于目录能力验证；正文解析外部接口与模型输出受控替代，真实云端质量另行实测。界面测试消费真实契约并检查七种题型及来源。

独立目录保存另有实际文件库关闭/重开测试，核对指纹加载、零正文资产和重复确认。桌面 DOM 集成走真实 Query、Hook、识别及导入组件，检查动态物理页、保存失败可重试、重进后自动展示已存目录，且不重新请求目录探测/模型。

Windows 原生多页推理记录线程 CPU 增量及逐页/批次耗时，结果在 `.studio-internal/textbook-ocr-measurements.json`。CPU 采样不能区分 ONNX 内部线程和 Rayon worker，接口没有独立渲染计时；不承诺固定加速倍数。正式门禁：`bun run test:all`、`bun run typecheck`。分阶段结果、需求对应测试及最终运行环境见[集成验收记录](textbook-import-verification.md)。


## MinerU 正文解析升级（2026-10-01）

目录保留局部范围探测与原目录页视觉提炼，页码仍默认使用本次目录结束页换算。MinerU 不承担目录最终语义提炼。旧的扫描正文 OCR 生产者及其专属设置已经删除；用于目录探测的真实 OCR 保留。

云端使用精准 V4 上传/轮询/ZIP，凭据只从本机 Gateway 环境读取 `MINERU_TOKEN`。本地模式调用用户显式指定的本机 V1 HTTP 服务，不自动安装模型、不静默降级或切换服务。任务按章节及可配置页数限制裁切，映射始终保留原 PDF 物理页。云端只在任务完成并下载结果包后产生章节材料，不声称提供逐页流式识别。

云端读取实际逐页 `_model.json`，避免已发现的后处理跨页生词表错合并。本地读取当前 `structured_content`，不兼容已废弃 `/file_parse`。结构化页块统一包含 `id/page/kind/text/bbox/rows`，表格 HTML 只安全提取单元格；不注入桌面 HTML。模型提示词发送目录路径和完整子树、实际页块与表格行，所需表格/图片页由 PDF 运行时渲染后作为图片附件送入 Turn，不让模型反向索要已知材料。

有界队列对解析生产者施加背压，固定会话复用、乱序逐章事务保存。轮询或下载失败后，本次执行内保留远端任务身份，继续同一任务；已成功页段不重复解析。取消停止 Gateway 等待和后续提交，已被服务接受的任务可能继续；进程重启后的远端任务续接不是本轮实现能力。

`sourceRefs` 保存于规范 AST 与章节 `content_json`；原书内容及原书例句在具有解析块的任务中必须引用当前 `blockId`，可加 0 起表格行号；物理 `page` 由系统查对应材料块后保存。错误块、行先拒绝并提供具体反馈，零写入；模型修正后再保存。来源定位、目录覆盖和字段格式不等于语义准确性证明。解析文字不作为第二份正式教材底稿。AI 讲解和练习继续单独注明来源；音调不能确认时省略，不按编号猜测。

官方接口与输出说明：[云端 V4](https://mineru.net/apiManage/docs)、[本地 V1](https://opendatalab.github.io/MinerU/usage/http_api/)、[输出契约](https://opendatalab.github.io/MinerU/reference/output_files/)。

### 桌面配置和本地部署入口

“内容提取配置”提供云端精准解析/本地部署选择。云端凭据只在运行 Gateway 的本机环境配置 `MINERU_TOKEN`，开发阶段根 `.env` 可使用现有 Bun 环境加载；修改凭据后重新启动 Gateway。界面只显示是否配置，实际有效性和额度以请求回执为准。

本地模式填写已经启动的本机 V1 服务地址并选择 Basic/Standard/Advanced。本应用不会安装 Python、模型或在后台切换解析方式；需要先按官方部署指南启动服务，例如：

```shell
mineru-kit api-server --host 127.0.0.1 --port 8000 --tier standard
```

上例端口仅为部署命令示例，应用没有硬编码该地址或端口。若本地服务开启认证，在 Gateway 本机环境设置 `MINERU_LOCAL_TOKEN`；云端 Token 不发送到本地服务。当前机型首次本地运行建议解析并发 1，实际档位和并发仍由用户显式决定。接口集成通过不表示本机模型已安装或推理性能已实测。

运行详情按章节折叠解析任务，详情可读远端身份、进度与重试；“章节材料已就绪”可展开逐页表格和块位置。实际模型提示词及原页附件可展开，候选及当前保存版本可查看 `sourceRefs`。已结束模型交互仍默认折叠，当前交互展开，查询始终限定本次 trace。
