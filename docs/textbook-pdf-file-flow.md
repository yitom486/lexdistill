# 教材本机 PDF 读取流程

更新：2026-10-04。取代教材导入的 MinerU、本地 OCR、Azure OCR 和预先上传图片流程。

## 目录

未指定目录范围时，Gateway 用 pdf-lib 裁剪原文件的前 `min(30, 页数)` 页。用户也可以指定完整的物理页范围。范围无效时明确拒绝，不默默改用默认值。

目录专精会话只声明 `library.propose_toc`。提示词给出裁剪 PDF 路径、本机阅读命令及文件页与原文件物理页的对应关系。模型输出真实父子目录、印刷页码、实际目录结束物理页；只有核对过映射才能填写 pageOffset。提供了前 30 页不代表目录结束于第 30 页。没有找到目录时提示调整范围，不扫描整本书或编造目录。

## 正文

1. 用户确认目录，系统按一级标题分组，子标题仅作为当前任务参考。页码边界取相邻一级标题，不根据教材名称或标题类型硬编码。
2. 全部待处理章节先裁剪到本次任务的临时目录，之后才经 agentpools 执行器启动连续 Worker（`AgentPool` API v2、`sharedProcess`，复用 `D:\project\rust\agentpools` 现成池/lease，不自建池）。
3. 默认最多 6 个 Worker，用户已保存的模型、思考等级和并发偏好经 `mcpServers`/`model`/`effort` 真实注入（approval `never` + `windows.sandbox="unelevated"`）。同一 Worker 连续处理不同章节（连续会话，历史真实保留），故障时由池重建会话。不同 Worker 经每 Worker 独立 MCP 端点隔离，不共用线程。
4. 每轮明确当前文件和章节。原生内容工具多次校验、暂存，模型完成且没有未修正错误时，每章一次事务保存。无内容的类别不用调用；不要求每章同时出现词汇、语法和练习。
5. 暂时性数据库错误仅重试保存；结束、取消、超时及旧原生轮次写入被拒绝。已保存章节保留。
6. 任务结束或取消后先关闭工作会话，再清理本任务目录。Worker cwd 是稳定父目录，避免删除被用作 cwd 的目录。清理只允许已核对归属的 import-* 子目录，不删除用户原 PDF。

## 文件读取边界

这不是把 PDF 二进制作为模型附件上传。Gateway 将裁剪文件路径和实际可运行的阅读命令交给支持本机文件读取的 Adapter。Codex Adapter 传递固定 cwd 和 workspace-write；其他 Adapter 必须明确声明支持，否则返回能力错误。

阅读器使用 Node.js 和现有 pdf-inspector/PDFium。文字页直接提取文字层；扫描页由 Agent 按需渲染并用原生图片查看工具查看。渲染每批最多 8 页来自真实 PDFium 限制，整章 PDF 没有旧的 32 MiB 图片附件预算。不安装 Python、OCR 模型或 ONNX Runtime，也不请求云端解析。保留 PDFium 是为了读扫描页，不是恢复旧 OCR 流程。

会话复用会保留历史；系统保证写入归属和旧轮次拒绝，提示词要求只读本轮文件。不能把这些措施宣称为模型完全没有历史或保证教材语义绝对正确。

## 后台启动与运行详情（2026-10-05）

Windows 上，Gateway 启动 Codex App Server 时显式传递 `-c windows.sandbox="unelevated"`。此项只选择普通用户 Windows 沙箱实现；章节使用的 workspace-write、目录访问边界和命令审批策略仍分别生效。该配置覆盖个人配置里 elevated 的默认值，避免由应用在后台调用提权沙箱初始化。设置仅作用于应用启动的 App Server，不修改用户其他 Codex 客户端的个人配置。官方说明：[Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox)。

运行详情为页面内按需展开的区域；章节整行不再打开大弹窗。默认显示材料摘要、模型和调用状态，原始提示词、完整路径、工具参数及线程身份按需展开。新的正文任务生成独立 traceId；读取旧 trace 时仍按 jobId 或最新 task.started 隔离，旧 MinerU 输入不得混作当前任务。已保存的历史记录保留原文，不能用新文案伪装成新流程。

本次后台启动配置与展示修正尚未通过运行门禁；用户明确禁止系统授权弹窗后，停止了会触发当前编码环境授权的命令。此前 PDF 流程全量通过的结果不能当作本次新增修改的测试结果。普通用户沙箱的实际本机启动、文件读取和 UI 行为仍待无提权环境验证。

## 验证

真实 PDF 测试覆盖裁剪页顺序、文字读取、扫描页按需渲染、全部文件先准备、连续 Worker、迟到写入拒绝、SQLite 事务、取消、清理、目录草稿到保存的层级保持及默认 30 页。模型输出由受控 Adapter 注入，不能用这些测试代替真实整本教材的识别质量验收。

正式门禁：`bun run typecheck`、`bun run test:all`。生产部署需要安装可运行的 Node.js，首次使用会准备经 pin 校验的 PDF 原生库；打包后的机器环境和长教材质量仍须实际验收。UI 视觉验收由用户完成。
