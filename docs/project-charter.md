## 1. 产品愿景与核心用户价值

### 1.1 愿景定义
**LexDistill** 是一款面向外语学习者（初期聚焦**日语**与**英语**）的 AI 自适应外语学习系统。

与传统“以大语言模型为中心的纯文本聊天框”或“纯多媒体播放壳”不同，LexDistill 的核心定位是：
> **以学习者状态为中枢、以做题与卡片为练兵场、以 AI 为自适应出题与智能批改导师的完整教学闭环。**

系统能够长期追踪学习者的知识点掌握度、主动发现语言缺陷与相对优势、依据记忆衰减曲线智能调度复习，并在做题与答题过程中提供如真人名师般的错因诊断与母语负迁移分析。

### 1.2 核心用户价值主张
1. **靶向攻坚，告别题海战术**：
   - 传统学习者刷题往往是随机题库，大量时间浪费在已掌握内容上。LexDistill 根据用户的“薄弱项雷达”，由 AI 针对未掌握词汇、易混淆语法实时生成针对性测验。
2. **错因穿透，知其然并知其所以然**：
   - 传统软件只告知“对”或“错”。LexDistill 提供多维度批改卡：指出错因分类（助词混淆/时态错位/语序倒装）、深度解析认知盲区、提供地道表达升级建议。
3. **沉淀终身学习资产，摆脱模型绑定**：
   - 用户的生词本、错题本、语法掌握度与复习历史具有独立生命周期。底层不论切换 Codex、Claude、Gemini 还是本地离线大模型，用户核心数据永不丢失。
4. **渐进式语境拓展**：
   - 在巩固核心练习与卡片的基础上，逐步接入经典教材（如《标准日本语》、《大家的日语》）结构化体系及音视频多媒体，实现“学-练-测-用”全场景覆盖。

### 1.3 产品形态与平台优先级
- **桌面端是主产品**：提供完整学习闭环与当前完整的 Agent 辅导能力；Tauri 负责桌面封装，Gateway Sidecar 在本机承接业务、存储与 Agent 调度。
- **浏览器不是独立发行目标**：React 界面继续作为桌面 WebView 的实现，并可用于开发、预览与调试；是否维护面向普通用户的浏览器产品不作为当前战略承诺。
- **Android 是后续轻量伴随端**：优先覆盖卡片复习、学习记录等移动场景，不要求手机本地运行 Agent / ACP，也不纳入当前桌面主线交付。
- **移动端联网、跨设备同步与离线数据策略尚未定案**：启动 Android 实施前，先根据用户场景决定使用远程 Gateway 还是移动端本地实现；不假定桌面 Sidecar 可直接移植。
- **移动端 Agent 保持可选**：若未来确认有移动端 AI 需求，优先由可访问的远程 Gateway 执行 Agent；手机仅作为客户端。手机本地 Agent 不列为目标。

## 2. 核心系统定位与边界原则

### 2.1 架构四大硬性约束
1. **业务核心不得绑定任何具体 Agent / LLM 厂商**：
   - 领域模型（Learner Core）与业务流程严禁直接 `import` 任何外部 AI SDK（包括 Codex、OpenAI、Claude、ACP、MCP）。
   - 核心系统仅依赖统一抽象：`AgentAdapter`、`AgentSession`、`AgentEvent`、`Tool`、`LearnerState`。
2. **第一阶段首发优先原生对接 Codex App Server**：
   - Codex App Server 是第一阶段的主力 Agent 运行时。
   - 不通过简化的 ACP 协议阉割 Codex App Server 的 Thread、Turn、Item、流式输出、动态工具与沙箱审批能力。
   - 所有 Codex 原生能力由专有适配器 `packages/agent-runtime/src/adapters/codex` 进行双工桥接，绝不向业务层渗透。
3. **划分 Context Snapshot 与 Tool 调用的刚性边界**：
   - 高频已知状态（当前做题上下文、当前选中生词、学习者目标语言与能力等级）作为不可变快照随 Turn 发送。
   - Tool 仅用于“获取未知信息（如权威词典检索）”或“触发持久化状态变更（如错题写入、熟练度更新）”。
4. **客户端只直连 Agent Gateway**：
   - 桌面端、浏览器运行态与未来 Android 客户端只与自研 Agent Gateway 通信，不直接暴露模型端点；浏览器运行态是共享界面的运行方式，不等同于独立 Web 产品目标。

## 3. MVP (第一阶段) 交付范围与非目标

### 3.1 MVP 核心功能范围 (In-Scope)
- **主产品交付平台**：Tauri 桌面端，具备完整学习闭环与 Agent 能力；浏览器用于共享界面的开发、预览和调试。
- **学习卡片系统 (Flashcards)**：
  - 生词卡、核心语法卡、易混辨析卡；
  - 引入 FSRS（Free Spaced Repetition Scheduler）间隔复习调度；
  - 熟练度自评与记忆曲线衰减跟踪。
- **互动做题与练习 (Exercises & Quiz)**：
  - 客观题：单选题、完形填空、词块重排（本地即时秒判）；
  - 主观题：双向句子翻译、情境造句（AI 深度评估）。
- **AI 靶向出题与智能批改 (AI Question Gen & Grading)**：
  - 基于学习者最近薄弱项动态生成针对性题目；
  - 结构化批改报告：得分、正误评级、错因诊断、地道表达建议。
- **学习者能力画像与全功能错题本 (Learner State & Mistake Notebook)**：
  - 动态统计“相对优势”与“当前缺陷”（雷达图数据基础）；
  - 错题记录自动归因分类、订正重练与攻克状态追踪。
- **通信与运行时底座**：
  - Bun Monorepo 体系；
  - Agent Gateway 双向 WebSocket 通信协议；
  - 基于 Codex App Server 的 `CodexAdapter` 适配器。

### 3.2 第一阶段明确非目标 (Non-Goals / Out-of-Scope)
- **非目标 1：全功能流媒体与视频播放器**  
  初期不花费精力攻克复杂音视频编解码、外挂字幕实时提取等边缘难题（保留架构接口，后续里程碑支持）。
- **非目标 2：全自主自由聊天机器人 (Freeform Open Chat)**  
  不盲目做一个通识型聊天窗口，所有 AI 对话均围绕具体题目、词汇释义或语法辅导展开。
- **非目标 3：重型分布式微服务集群**  
  首期坚决采用“模块化单体 (Modular Monolith)”，避免不必要的网络开销与运维复杂度。
- **非目标 4：自建复杂云端向量库中台**  
  在核心题库与做题闭环成熟前，不盲目搭建重型向量检索中台。
- **非目标 5：手机本地运行 Agent / ACP**
  Android 首期定位为轻量学习伴随端；不在手机捆绑桌面 Gateway Sidecar 或 Agent Runtime。远程 AI 能力需有明确需求后单独评估。

## 4. 技术决策价值观

1. **简单与稳定重于“技术炫技”**：
   - 首选高确定性、低认知负担的方案（Bun、TypeScript 严格模式、Vite、React 19）。
2. **端到端类型安全 (End-to-End Type Safety)**：
   - 协议契约、领域模型、存储模式与前端组件共享 100% 静态 TypeScript 类型推断，杜绝 `any` 蔓延。
3. **桌面本地优先与分阶段多端 (Desktop Local-First & Staged Clients)**：
   - 桌面端本地运行 Gateway 与 SQLite；浏览器与桌面复用 React 界面。Android 复用协议与领域契约，但需单独设计移动端 Gateway 部署、数据同步与离线策略，不承诺零适配移植。

## 5. 核心技术风险清单

1. **AI 出题结构失真与难度漂移** -> 强制采用 Zod Schema 运行时校验与用户能力锚点注入。
2. **主观题批改标准不一致** -> 制定分级打分原则与强约束 JSON 结构化评分卡。
3. **AI 交互迟滞影响做题节奏** -> 引入四级路由，客观题 0ms 本地秒判，主观题流式异步反馈。
4. **学习记录并发冲突与状态漂移** -> 采用追加式学习日志（Append-only Event Log）与 SSOT 单一真实数据源。
5. **桌面与 Android 运行拓扑不同** -> 统一面向 Gateway 契约；桌面本地 Sidecar 已落地，Android 的远程或本地运行方案在排期前决策。
